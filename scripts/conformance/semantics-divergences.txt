# The semantics area's classified differences, read by generate_semantics_vectors.py.
#
# A line `reason <key>: <text>` defines a reason. A line `<engine> <key> <id>` classifies the vector <id> as a
# divergence of <engine> for that reason: the generator writes the field divergence.<engine>: <text>. A normative
# vector becomes a divergence. An impl-defined one stays impl-defined: its per-engine.<engine> field is the
# expectation that engine's records commit it to, and the divergence field says the engine does not meet it yet
# (SCHEMA.md section 5). The vector's expected value never changes.
#
# A line is added in a new corpus revision, with a dated row in conformance/vectors/REVISIONS.md, and is removed only
# the same way, when the engine's cut-over corrects the difference (decision D61, the route the syntax vectors took).
# Every reason names the row of bundle sjl-15-001's correspondence from code (Broiler.VM's
# docs/evidence/sjl-15-001/correspondence.md, whose Broiler.JS column is this repository's
# docs/evidence/sjl-15-001/correspondence-broiler-js.md) whose answer the engine gives in the difference, which is a
# row the vector's note names; the engine's answer as that row records it; the row's class across both engines; and
# the record that answers it: for Broiler.VM, SJL-15.3, its lowering on the model (JSD-0088, and the classes of its
# bundle sjl-15-001's rule); for Broiler.JS, SJL-15.5, its compiler on the model, whose bundle sjl-15-001's rule lists
# this engine's corrections by row before any run (corrections.md, classes T and C1). A reason is in ASCII.
#
