# The syntax area's classified differences, read by generate_syntax_vectors.py.
#
# A line `reason <key>: <text>` defines a reason. A line `<engine> <key> <id>` classifies the vector <id> as a
# divergence of <engine> for that reason: the generator writes the field divergence.<engine>: <text>. A normative
# vector becomes a divergence. An impl-defined one stays impl-defined: its per-engine.<engine> field is the
# expectation that engine's records commit it to, and the divergence field says the engine does not meet it yet
# (SCHEMA.md section 5). The vector's expected value never changes.
#
# A line is added in a new corpus revision, with a dated row in conformance/vectors/REVISIONS.md, and is removed only
# the same way, when the engine's cut-over corrects the difference. Every reason names the row of bundle sjl-13-001's
# correspondence from code (Broiler.VM's docs/evidence/sjl-13-001/correspondence.md) whose answer the engine gives in
# the difference, which is the row the vector's note names; the engine's answer as that row records it; the class
# Broiler.VM's JSD-0083 gives the row; and the record that answers it: for Broiler.VM, step 1 of SJL-13.3, its wide
# path's cut-over to the shared syntax library, which JSD-0083's section "The corrections step 1 makes" lists; for
# Broiler.JS, SJL-14, its cut-over, whose corrections.md lists this engine's corrections (decision D45), or, for the
# `m` suffix, decision SJL-D-17 of docs/roadmap/SharedLibraries.md, under which the extension stays in this engine as
# a parameter of the shared lexer. A reason quotes the row's cells shortened (" ..." marks a cut) and in ASCII.
#
