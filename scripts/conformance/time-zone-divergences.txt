# The time-zone area's classified differences, read by generate_time_zone_vectors.py.
#
# A line `reason <key>: <text>` defines a reason. A line `<engine> <key> <id>` classifies the vector
# <id> as a divergence of <engine> for that reason: the generator writes the field
# divergence.<engine>: <text>, and a normative vector becomes a divergence. An impl-defined vector
# stays impl-defined, the field classifying the engine's difference from its own per-engine
# expectation. The vector's expected value never changes (SCHEMA.md section 5).
#
# A line is added in a new corpus revision, with a dated row in conformance/vectors/REVISIONS.md,
# and is removed only the same way, when the engine's cut-over corrects the difference and lists
# the correction. Every reason names the row of bundle sjl-8-001's correspondence from code
# (Broiler.VM's docs/evidence/sjl-8-001/correspondence.md) it confirms, the class JSD-0076 gives it
# (a correction under decision SJL-D-16 (a), or a policy difference under SJL-D-20), and the plan
# that answers it, milestone SJL-8.6, this engine's cut-over to the data home's tables and the shared
# zone algorithms.
#
# Revision 22, 2026-10-17: every difference of Broiler.JS's first engine-level run on the time-zone
# area, at revision 21, under TZ=UTC and under TZ=America/New_York (docs/evidence/sjl-8-001/engine/).
# The two runs differ on the same vectors with the same renderings: no vector of the area depends on
# the host's zone.

reason js-z1-z2-release: rows Z1 and Z2: Broiler.JS's tzdata.bin is tzdb 2025b, copied from a build host, and SJL-D-20 pins 2026e, whose changes it lacks (2025c Baja California's DST in 1953 and 1961 to 1975; 2026a Moldova's EU transition times since 2022; 2026b British Columbia's permanent -07; 2026c Alberta's permanent -06 and Morocco's permanent +00; 2026d the Northwest Territories' permanent -06, Colombia 1992 and Iran 1979; 2026e Manitoba's permanent -05 and Ireland's 1925 fall back); policy difference under SJL-D-20 (the release), answered by SJL-8.6
reason js-z3-backzone: row Z3: Broiler.JS's tzdata.bin holds backzone's Zones for zone.tab's names and points fifteen Links elsewhere, and SJL-D-20's default build has no backzone, so each of these names reads its link target's history before 1970; policy difference under SJL-D-20 (backzone), answered by SJL-8.6
reason js-z4-extrapolation: row Z4: Broiler.JS reads only the TZif data block and keeps the offset of the last transition of 2037 for every later instant, so northern zones stay on standard time and southern ones on daylight time, where SJL-D-20 continues the recurring rules without limit; policy difference under SJL-D-20 (extrapolation), answered by SJL-8.6
reason js-a5-extrapolation-wall: row A5: after 2037 Broiler.JS's frozen offset (row Z4) has no gap and no overlap, so a skipped or repeated wall time names one instant and reject accepts it; policy difference under SJL-D-20 (extrapolation), answered by SJL-8.6
reason js-a7-extrapolation-day: row A7: after 2037 a day starts at midnight in Broiler.JS, and has 24 hours, because its offset froze (row Z4), where the recurring rules skip midnight or change the offset that day; policy difference under SJL-D-20 (extrapolation), answered by SJL-8.6
reason js-a10-extrapolation-transitions: row A10: Broiler.JS's transitions end with tzdata.bin's table in 2037, so it answers no next transition after it and the last of 2037 as every later previous one; policy difference under SJL-D-20 (extrapolation), answered by SJL-8.6
reason js-z5-factory: row Z5: Broiler.JS's tzdata.bin holds Factory, which SJL-D-20's default build does not compile, so it accepts and lists the name; policy difference under SJL-D-20 (Factory), answered by SJL-8.6
reason js-z5-z7-listed: rows Z5 and Z7: Broiler.JS lists the names that are their own tzdb link target, which leaves out eleven that CLDR keeps as primaries and adds Factory; policy differences under SJL-D-20 (CLDR primaries, Factory), answered by SJL-8.6
reason js-z7-primaries: row Z7: a name's primary in Broiler.JS is its tzdb link target, and twelve names that CLDR keeps as primaries are links there (America/Kralendijk, Lower_Princes, Marigot, St_Barthelemy, Arctic/Longyearbyen, Atlantic/Jan_Mayen, Europe/Bratislava, Busingen, Mariehamn, Podgorica, San_Marino, Vatican); policy difference under SJL-D-20 (CLDR primaries), answered by SJL-8.6
reason js-z10-lookup: row Z10: Broiler.JS folds a name with the runtime's invariant upper-casing, which maps U+017F to S, so it admits a name that GetAvailableNamedTimeZoneIdentifier's ASCII-case-insensitive match refuses; correction under SJL-D-16 (a), answered by SJL-8.6
reason js-z11-formatter-iso: row Z11: Broiler.JS's formatter reads an ISO date-time string's zone annotation, or its Z as UTC, where CreateDateTimeFormat takes only an offset string or an available name and throws a RangeError otherwise; correction under SJL-D-16 (a), answered by SJL-8.6
reason js-z12-regions: row Z12: Broiler.JS answers getTimeZones from a hand table of fourteen regions, else UTC, where both plans answer zone.tab's zones of the region, which Broiler.JS's own per-engine expectation holds; correction under SJL-D-16 (a), answered by SJL-8.6
reason js-a13-digits: row A13: Broiler.JS matches an offset's digits with .NET's \d, which admits every decimal digit, and its int.Parse then lets a FormatException escape the evaluation; the offset grammar's digits are ASCII, so the string is neither an offset nor an available name, a RangeError; correction under SJL-D-16 (a), answered by SJL-8.6
