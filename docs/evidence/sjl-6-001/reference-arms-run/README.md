Arm J's kinds are differences of `parse, Broiler.JS's order`, where S reads the strict dialect and then

## 7. The negative controls

`compare-date --controls` ran the rule's two copies once (`negative-control/`), from the comparison commit,
restricted to the operations they change: arm V's `DateParseText` charging one unit more for the string
`"1970"`, and arm J's `JSTemporalPlainDate.DaysFromCivil` answering one day more for 1970-01-01
(`negative-control/differences.tsv`):

- arm J's copy: one difference, E3D line 1464574 (`1970 1 1`): `f64:0000000000000000` from S,
  `f64:3FF0000000000000` from the copy;
- arm V's copy: the planted change at both lines of the population that hold `"1970"`, E5F line 1358289 and
  E5V line 20352, each `f64:0000000000000000|charge:5` from S and `…|charge:6` from the copy; and 80 more,
  the very inputs and results of arm V's own 80 differences of P9's reading, which a copy of arm V repeats.

The classifier leaves all 83 differences of the two copies unclassified, as a negative control. **The
judgement:** the first revision's section 4 says each copy "must be reported as exactly one difference". The
planted change is one change for one input, and it was reported at every line that holds that input and
nowhere else, so this bundle reads the control as reported once per line of its input. Read as one line of
the listing, arm V's control would not meet that sentence; the MET line's own clause, that both controls were
reported unclassified, holds under either reading.

As the rule asks, the copies were then removed, with the `--controls` option, at `6f29deb`;
[`negative-control/controls.patch`](negative-control/controls.patch), applied with `git apply`, restores them.

## 9. Commands

From the repository root, with `$P` the population directory and `$R` the run directory; the process's zone

```sh
git checkout b75d12e9afa51a0f9bbf59877f6c2d86e244e96b
python3 scripts/conformance/generate_date_population.py --out $P      # checked against population-manifest.json
dotnet build Broiler.ECMAScript/Broiler.ECMAScript.Algorithms.Tests -c Release
TZ=UTC dotnet Broiler.ECMAScript/Broiler.ECMAScript.Algorithms.Tests/bin/Release/net10.0/Broiler.ECMAScript.Algorithms.Tests.dll \
    compare-date --population $P --out $R > $R/comparison.log
python3 scripts/conformance/classify_date_arms.py --run $R

# the culture runs, and the negative controls, from the same commit
TZ=UTC dotnet .../Broiler.ECMAScript.Algorithms.Tests.dll compare-date --population $P --out $C --culture sv-SE   # and fa-IR, ar-SA
TZ=UTC dotnet .../Broiler.ECMAScript.Algorithms.Tests.dll compare-date --population $P --out $N --controls
python3 scripts/conformance/classify_date_arms.py --run $N    # both copies unclassified

# the first run: the same at 5501705fad471d9b98a34dab86a76c3cd5983392
```

Each `comparison.log` ends with the command's exit status, which the shell that ran it appended.
