How the engine-level runs in this directory were taken (SJL-17.2, the collation vectors, 2026-11-02 UTC).

They are each engine's first run on the collation vectors, at corpus revision 33, which revision 34 classifies, and
both engines' runs on revision 34. They are no part of bundle sjl-17-001's rule, whose parts are taken at the commits
the rule names, and nothing here is a verdict.

Host, for every run here: Ubuntu 24.04.5 LTS; Linux 6.18.44 x86_64; 4 logical CPUs; ICU 74.2 (the package libicu74
74.2-1ubuntu3.1, the only ICU installed), which .NET's globalization loads and whose CompareInfo Broiler.JS's
Intl.Collator reads; dotnet SDK 10.0.401, runtime Microsoft.NETCore.App 10.0.12. Other work shared the machine
throughout, so no run here is a timing.

Every Broiler.JS run reads a scratch tree written by git archive of the commit it names, built once beforehand with
  dotnet build Broiler.JS/Broiler.JavaScript.Vectors.Tests -c Release --disable-build-servers
(no warning), and is
  env -u LANG -u LANGUAGE -u LC_ALL BROILER_VECTORS_WORKERS=4 TZ=UTC BROILER_VECTORS_REPORT=<report>
    dotnet test Broiler.JS/Broiler.JavaScript.Vectors.Tests -c Release --no-build --logger "console;verbosity=normal"
with four evaluating processes, as CI's engine vectors job runs the corpus, the invariant culture (no LANG, LC_ALL or
LANGUAGE) and TZ=UTC only: bundle sjl-17-001's rule takes no zone (JSD-0084 decision E10). Its negative control
changes numbers/to-fixed/0001 in a copy of the corpus and is written beside its report. Each Broiler.VM run is, at
b43d0bb2ab2e827c754c97bce8024cb717e7ceef (its default branch, Broiler-Platform/Broiler.VM#180), built once beforehand
in a scratch tree written by git archive with
  dotnet build src/compositions/Broiler.VM.Composition.JavaScript.Conformance -c Release --disable-build-servers -warnaserror
  env -u LANG -u LANGUAGE -u LC_ALL TZ=UTC dotnet
    src/compositions/Broiler.VM.Composition.JavaScript.Conformance/bin/Release/net10.0/Broiler.VM.Composition.JavaScript.Conformance.dll
    --vectors <archive> --expect <pin> --report <report> [--mutate intl/collation/options/sensitivity/0001]
on a scratch archive written twice by
  git archive --format=tar.gz <commit> -- conformance/vectors ':(exclude)conformance/vectors/controls'
byte for byte the same, the second hashed for the scratch pin kept here (never committed to Broiler.VM). The archive
is corpus-r33.tar.gz or corpus-r34.tar.gz in the logs' headers. Each log was written whole by the run's script: a
header naming the commit, the build, the corpus, the host and the command, then the runner's output, then the exit
code and the end time. Every run's summary line names the 18 status vectors it skipped.
