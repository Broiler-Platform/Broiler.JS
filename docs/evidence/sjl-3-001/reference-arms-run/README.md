# Bundle SJL-3-001, the reference-arm comparison: the shared number conversions against both engines' pre-cut-over code

**Milestone:** SJL-3.3 of the shared JavaScript libraries programme
(`Broiler.VM/docs/javascript-shared-libraries/milestones/sjl-3-number-conversion-pilot.md`).
**Rule:** [`../reference-arms.md`](../reference-arms.md), written at SJL-0.9, as revised before this
run by [`../reference-arms-revised-2026-10-12.md`](../reference-arms-revised-2026-10-12.md), which
changed how the output is read and retained and nothing the rule decides. **Evidence class:** a
library-level conformance comparison; not a measurement. **Owner and reviewer:** one person holds
every role (Broiler.VM's exception EX-30); nobody independent has read this run.

| The negative control was reported unclassified | Yes: the comparison reported the planted results as differences and classifies nothing | `negative-control/` |

**The first classification did not meet it**, and the bundle keeps it (`first-classification/`).
Read against corpus revision 3, 28 differences were unclassified, all of one kind: Broiler.VM's
`parseInt` at radix 10 on a string of more than 20 significant digits, where the clause admits the
value of the first 20 digits followed by zeros and the two values round to different doubles. Both
results were admitted (class (b)), but no vector held both options at radix 10, and the rule holds
such a difference unclassified "until a vector at a new corpus revision covers it". Corpus revision 4
added those vectors (`conformance/vectors/REVISIONS.md`), and the classification was run again on the
same comparison, unchanged: 0 unclassified.

**Arm J's literal row counts four class (a) differences more than the comparison found.** They are
the inputs `07.5` and `07e1`, sloppy and strict, which S refuses and arm V admits. Arm J is not called
for a literal S refuses (`summary.json`, `notImplemented`), and the comparison writes `(not called)`
in its place; the classifier, as committed, reads that marker as a result and classes it "admits a
literal the grammar refuses". They are not arm J's results. The comparison's count, 8352, is the arm's.

`summary.json`'s `notImplemented` names the operations an arm has no member for, with the reason:
canonical numeric strings in both arms and the array-index test in arm V (each engine has them outside
the copied lists), arm J's literal refusals, and arm J's `TryCoerceToUInt32`.

**Arm J's `unfinished:` results.** Arm J's `RefineEstimate` is held to 1,024 steps
(`"stepCap": 1024`); a result that reached the cap is reported with its estimate. Every one is class
(a): each estimate is more than 2^20 units in the last place from every admitted value, so the cap
changed no result the rule judges. They are the groups "does not finish: its estimate is N units in
the last place away", one per distance, which is why `classification.json` has 41,776 groups.

## 5. The classifier's change in this commit

The classifier committed at `7565c36` read the whole difference listing, 28,625,695 lines, into
memory before classifying it. This commit makes it read the listing in the same chunks of 2,000 lines,
in the same order, as the worker pool asks for them, and writes its own listing at gzip level 6
instead of 9. Nothing it decides, counts or digests changed: the digests are over the uncompressed
text. Both classifications of this bundle were run with the changed script.

## 7. The negative control

`negative-control/arm.patch` changed arm J's `ToECMAString` for one double, the smallest normal one
(bits `0010000000000000`), to answer its string with the exponent off by one, and the comparison ran
`Number::toString` alone with that arm; the patch was then removed. The comparison reported the
planted result as a difference at three inputs (`negative-control/differences.tsv.gz`): D1 line 3, the
double itself; D1 line 9, its negative, because the arm writes a negative number as "-" and the string
of its magnitude; and D2 line 157, the same double in the exponent population. It classified none of
them, as it classifies nothing; with the patch removed, arm J's `Number::toString` differs nowhere
(section 3).

## 8. Commands

From the repository root, with `$P` the population directory, `$R` the run directory and `$N` the
negative control's:

```sh

python3 scripts/conformance/generate_reference_population.py --out $P      # checked against population-manifest.json

    compare --population $P --out $R > $R/comparison.log

dotnet build Broiler.ECMAScript/Broiler.ECMAScript.Algorithms.Tests -c Release
dotnet Broiler.ECMAScript/Broiler.ECMAScript.Algorithms.Tests/bin/Release/net10.0/Broiler.ECMAScript.Algorithms.Tests.dll \
    compare --population $P --out $N --operations Number::toString > $N/comparison.log
```
